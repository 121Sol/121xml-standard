How 121XML Works

A complete request flows through layers of translation to a unified engine

1

External Request

REST API, gRPC, GraphQL, WebSocket with any schema

2

Protocol Adapter

Convert incoming protocol to 121XML format

3

Schema Translator

Translate schema to 121XML (JSON→XML, Proto→XML, etc.)

4

Core Engine

Process unified 121XML in single engine

5

Response Adapters

Convert 121XML back to original protocol/schema

6

Response Sent

Original system receives response in familiar format

🎬 Data Flow Animation

Request: REST/JSON → Protocol Adapter → Schema Translator → 121XML Engine

Processing: State Manager → Tool Executor → Memory Manager → Permission Gate → Audit Log

Response: 121XML → Response Adapter → Schema Translator → REST/JSON

✓ Same request type works identically on REST, gRPC, WebSocket, GraphQL

Core Data Models

All 121XML objects and their relationships

🎯 Core 121XML Object

Every object in 121XML follows this base structure:

{ "object_id": "unique_identifier", "object_type": "definition | agent | tool | permission | workflow", "profile": "urn:121xml:core-object/1.0", "metadata": { "created_at": "ISO8601", "created_by": "user_id", "version": "1.0.0", "description": "Human readable" }, "content_address": { "hash": "SHA256_VALUE", "format": "data://sha256:HASH:TYPE" }, "signing": { "algorithm": "sha256WithRSAEncryption", "signature": "base64_encoded", "certificate": "cert_chain" } }

Key Benefits

  • Self-describing via profile URI
  • Immutable via content address (SHA256)
  • Digitally signed for integrity
  • Versioned for evolution
  • Metadata for discovery

🤖 Agent Definition

Agents are 121XML profiles containing model, tools, and protocol configuration:

{ "profile": "urn:121xml:agentic-app-agent/1.0", "agent_id": "email_classifier", "name": "Email Classifier Agent", "model": "claude-opus-5", "description": "Classifies emails and creates tickets", "available_tools": [ "data://sha256:tool_read:tool", "data://sha256:tool_classify:tool", "data://sha256:tool_create_ticket:tool" ], "supported_protocols": ["rest", "grpc", "websocket"], "configuration": { "temperature": 0.7, "max_tokens": 2000 } }

✓ Benefits

Agents are portable (export from Claude, import to GPT), versioned, and instantly deployable to any protocol.

🔐 Permission Grant Model

User-granted permissions are explicit, time-bounded, and instantly revocable:

{ "profile": "urn:121xml:permission-grant/1.0", "grant_id": "uuid", "user_id": "user_001", "system_id": "engine", "permissions": ["read", "execute"], "issued_at": "2026-08-06T10:00:00Z", "expires_at": "2026-08-07T10:00:00Z", "revoked_at": null, "status": "active" }

Three-State Model

  • Active: Grant is valid and permission checks pass
  • Expired: Grant reached expiration time
  • Revoked: User explicitly revoked access

⚙️ Workflow Definition (DAG-based)

Workflows orchestrate multi-step processes with conditional routing:

{ "profile": "urn:121xml:agentic-workflow/1.0", "workflow_id": "email_processing", "name": "Email Processing Workflow", "steps": [ { "step_id": "step_1_read", "type": "tool_call", "tool_id": "tool_read_email", "next_on_success": "step_2_classify", "next_on_failure": "step_error_handler" }, { "step_id": "step_2_classify", "type": "tool_call", "tool_id": "tool_classify_email", "next_on_success": "step_3_create_ticket" } ] }

Workflow Features

  • Sequential or parallel step execution
  • Conditional routing based on results
  • Error handling and recovery
  • Timeout and retry configuration
