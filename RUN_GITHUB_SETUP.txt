DETAILED USAGE
================================================================================

PARAMETERS:
───────────

-GitHubToken "token"
  Required. Personal access token from Step 1

-GitHubUsername "username"
  Optional. GitHub username (default: rashadkhan4mna)

-GitHubEmail "email"
  Optional. GitHub email (default: rashadkhan4mna@gmail.com)

-SourcePath "path"
  Optional. Path to 121AI files (default: current directory)


EXAMPLES:
─────────

1. Basic usage (recommended):
   .\setup-github-repos.ps1 -GitHubToken "ghp_xxxx..."

2. With custom username:
   .\setup-github-repos.ps1 `
     -GitHubToken "ghp_xxxx..." `
     -GitHubUsername "myusername"

3. With custom email:
   .\setup-github-repos.ps1 `
     -GitHubToken "ghp_xxxx..." `
     -GitHubEmail "myemail@example.com"

4. With custom source path:
   .\setup-github-repos.ps1 `
     -GitHubToken "ghp_xxxx..." `
     -SourcePath "C:\Projects\121AI"

EXECUTION POLICY:
─────────────────

If you get an error about execution policy:

  Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process -Force

This allows the script to run in the current PowerShell session only.

OR set permanently (requires admin):

  Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser


TROUBLESHOOTING:
────────────────

Git not found?
  → Install from: https://git-scm.com/download/win
  → Restart PowerShell after installation

GitHub token error?
  → Check token has correct scopes (repo, workflow, admin:org_hook)
  → Check token hasn't expired
  → Create new token and retry

Authentication failed?
  → Verify username is correct (rashadkhan4mna)
  → Verify email is correct (rashadkhan4mna@gmail.com)
  → Check internet connection

Repository already exists?
  → The script will fail if repo already exists
  → Delete existing repositories on GitHub first
  → Then run script again


AFTER SETUP COMPLETES:
──────────────────────

1. Go to https://github.com/rashadkhan4mna/121ai
2. Go to https://github.com/rashadkhan4mna/121xml-standard

3. For each repository:
   Settings → Branches → Add branch protection rule
   - Require pull request reviews before merging
   - Require status checks to pass
   - Include administrators
   - Allow force pushes: No
   - Allow deletions: No

4. Settings → Collaborators and teams
   - Add team members as needed
   - Assign appropriate roles

5. Add GitHub Actions secrets:
   Settings → Secrets and variables → Actions → New repository secret
   - DOCKERHUB_USERNAME
   - DOCKERHUB_TOKEN
   - AWS_ACCESS_KEY_ID
   - AWS_SECRET_ACCESS_KEY
   - etc.

6. Add GitHub Actions workflows:
   .github/workflows/
   - ci.yml (tests, builds)
   - security.yml (scanning, linting)
   - deploy.yml (deployment automation)
