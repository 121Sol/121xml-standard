🔄 Multi-Protocol Support

The Problem: Building multi-protocol agents requires separate implementations for REST, gRPC, GraphQL, etc.

121XML Solution: Write your agent once. Deploy to all protocols automatically.

# Same agent, all protocols agent = AgentDefinition( supported_protocols=["rest", "grpc", "websocket", "graphql"] ) # Automatically works on all four!

Result: 3x code reduction, zero protocol lock-in, future-proof architecture.

📊 Schema Agnostic Design

The Challenge: JSON Schema, Protobuf, GraphQL, XSD - incompatible formats that require custom adapters.

121XML Approach: All schemas translate to/from 121XML losslessly. One schema translator for each format.

Benefit: Same tool works with any schema combination. Add new schema types without touching agent logic.

🔗 SHA256 Content Addressing

How it works: Every 121XML object gets an immutable address based on its content hash.

Format: data://sha256:ABC123DEF:type

Benefits:

  • Perfect caching (address = unique cache key)
  • Tamper detection (modified content = different address)
  • Zero data duplication (only addresses shared)
  • Infinite scalability (addresses resolve globally)

🔐 User Data Sovereignty

Three-Layer Model:

  1. User Decision: "Grant Claude access to my data"
  2. Permission Grant: Explicit, time-bounded, instantly revocable
  3. Encrypted Storage: Data encrypted with user-held keys, never copied

Result: GDPR/HIPAA/CCPA compliant by design. Users stay in control.

Core Data Models

All 121XML objects represented as interactive models

Core Object Model

Every 121XML object follows this structure:

{ "object_id": "unique_identifier", "object_type": "definition | agent | tool | permission", "profile": "urn:121xml:core-object/1.0", "metadata": { "created_at": "ISO8601", "created_by": "user_id", "version": "1.0.0" }, "content_address": { "hash": "SHA256_VALUE", "format": "data://sha256:HASH:TYPE" } }

Key Features:

  • Self-describing via profile URI
  • Immutable via content address
  • Versioned for evolution
  • Digitally signed for integrity

Agent Definition Model

Agents are defined as 121XML profiles containing:

{ "agent_id": "agent_classifier", "name": "Email Classifier", "model": "claude-opus-5", "available_tools": ["tool_read_email", "tool_classify"], "supported_protocols": ["rest", "grpc", "websocket"], "configuration": { "temperature": 0.7, "max_tokens": 2000 } }

Benefits: Agents are portable, versioned, and instantly deployable to any protocol.

Permission Grant Model

User-granted permissions are explicit and revocable:

{ "grant_id": "uuid", "user_id": "user_001", "permissions": ["read", "execute"], "issued_at": "2026-08-06T10:00:00Z", "expires_at": "2026-08-07T10:00:00Z", "status": "active | revoked | expired" }

Model: Permissions gate all access. Instantly revocable. Time-bounded.

Workflow Definition Model

Workflows are DAGs of steps with conditional routing:

{ "workflow_id": "email_processing", "steps": [ { "step_id": "read", "type": "tool_call", "tool_id": "tool_read_email", "next_on_success": "classify" }, { "step_id": "classify", "type": "tool_call", "next_on_success": null } ] }

Model: Sequential or parallel steps, conditional routing, error handling.

Core Concepts Explained

Understanding the axioms and rules that make 121XML universal

🎯 A1: Composition Over Inheritance

Principle: All structure via nested maps, never class hierarchies.

Why: Enables representation in Rust, Go, C++, Python, JS without language-specific features.

Example: Instead of inheritance, compose objects:

# Instead of: class EmailAgent extends Agent # Use composition: { "agent": { "id": "...", "name": "..." }, "capabilities": { "read": true, "execute": true } }

📌 A2: Explicit Type Tags

Principle: Polymorphic fields MUST have explicit type markers.

Why: Enables schema-free parsing at receiver (no schema fetch needed).

Example:

{ "result": { "_type": "string", "value": "success" } }

📚 A3: Homogeneous Sequences

Principle: All array elements MUST be same type.

Why: Enables pre-allocation without knowing content.

Example:

{ "tools": [ { "id": "tool1", ... }, { "id": "tool2", ... } ] // All items are same "tool" type }

🔤 R4: Alphabetically Sorted Keys

Rule: All map keys sorted by Unicode code point.

Result: Deterministic byte order → Stable SHA256 hashing

∅ R5: Null is Explicit

Rule: Three states: value (set), null (known empty), absent (never set).

Result: No ambiguity between missing and empty values

🆔 R6: Profile URI

Rule: All objects declare schema via URI.

Result: Schema discovered at receiver, no schema fetch needed

🔐 R7: SHA256 Content Addressing

Rule: Immutable address: data://sha256:HASH:type

Result: Tamper detection + perfect caching
