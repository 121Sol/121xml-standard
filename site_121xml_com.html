The self-describing data standard

Data that carries its own meaning.

121XML packages any object as a signed, content-addressed bundle of facets — so a receiver decodes structure, semantics, rules, relationships, ownership and position without a shared schema. Built on proven standards, not instead of them.

Self-describing

Every packet inlines — or content-addresses — its own shape and context. No external namespace to pre-share.

Verifiable

One signature over the root CID. Deterministic bytes (sorted keys) mean the same object always hashes the same. Tamper-evident by construction.

Lossless & de-duplicated

Explicit null vs. absent for bit-perfect round-trips; shared facets stored once by address — a measured dedup ratio, not a slogan.

The standard · v4 self-contained semantic object

Axioms, rules, and the facet model.

Axioms

A1 Composition over inheritance — flat, predictable.

A2 Explicit type tags — self-describing.

A3 Homogeneous sequences — type-safe arrays.

Rules

R4 Alphabetically sorted keys — deterministic bytes.

R5 Explicit null vs. absent — lossless round-trip.

R6 Profile URI urn:121xml:type/ver — schema discovery.

R7 Content address cid:… — immutable, tamper-evident.

A 121 Object

A signed Merkle-DAG of content-addressed facets. The root address is the hash over the sorted set of facet CIDs plus provenance; one signature over the root makes the whole object owned and tamper-evident; a prev-CID chain gives git-like immutable history.

FacetCarries
payloadthe data values (name/value pairs)
shapestructure + validation constraints
contextsemantics — what each key means
rulesinference — how to derive new facts
relationstyped edges to other object CIDs (drives 121ObjectMap)
provenanceowner (DID/key), timestamps, prev version, signature
spaceoptional 4-D pose: position · orientation · valid-time · uncertainty

Inline or reference: any facet may be embedded (fully portable) or referenced by CID (compact, resolved local → peer → registry). Both verify to the same root hash.

Related standards

Standing on shoulders — and saying so.

A candid map of what 121XML reuses. We read it to you plainly because a standard you can trust is one that names its lineage.

Canonical bytes

JCS (RFC 8785), Canonical CBOR / DAG-CBOR give deterministic serialization. 121XML adopts, doesn't reinvent.

Content addressing

IPLD, multihash and CIDs are the addressing substrate — interoperable with the whole content-addressed ecosystem.

Self-describing

CBOR (RFC 8949) tags and Avro's embedded schema pioneered self-description; JSON-LD carries semantic context.

Provenance

W3C Verifiable Credentials, DID and PROV, plus IETF COSE signatures, express ownership and authenticity.

Geospatial 4-D

OGC Moving Features and MISB/STANAG 4609 (drone motion-imagery metadata) model position in space and time.

Vertical formats

ISO 20022, HL7 FHIR, EDI, GS1 — wrapped as profiles, contributed back to their bodies, never replaced.
