## DEEPSEEK ARCHITECTURE

### Current Flow
```
POST /api/chat/completions (DeepSeek API)
├─ messages (full history, reloaded each call)
├─ model (deepseek-chat or local variant)
├─ tools (JSON schema)
└─ stream (true/false)
    ↓
DeepSeek Processing
    ↓
Response (token-by-token or batched)
    ↓
Next call: Reload all history (78% waste)
```

### With 121XML
```
POST /api/chat/completions/121xml
├─ conversation_reference (data://sha256:...:conversation)
├─ tool_profiles (121XML)
├─ model (deepseek-chat)
└─ stream (true/false)
    ↓
Load by Address (immutable, no reload)
    ↓
DeepSeek Processing (full context via references)
    ↓
Response + Inference
    ↓
Append to conversation (no loss)
```

## UNIQUE DEEPSEEK FEATURES

### 1. Local Model Variant Support

DeepSeek offers both API and local models. 121XML enables seamless switching:

```xml
<map name="execution_context">
  <str name="api_or_local">api | local</str>
  
  <!-- If local -->
  <map name="local_config">
    <str name="model_path">/models/deepseek-chat-7b</str>
    <str name="quantization">q4 | q8 | full</str>
    <str name="device">cpu | gpu | mps</str>
  </map>
  
  <!-- If API -->
  <map name="api_config">
    <str name="endpoint">https://api.deepseek.com/v1</str>
    <str name="api_key_encrypted">user_managed_encryption</str>
  </map>
  
  <!-- Seamless switching via inference objects -->
  <seq name="inferences_by_context" of="map">
    <map>
      <str name="inference_id">inf_001</str>
      <str name="executed_on">api</str>
      <str name="result">content</str>
    </map>
  </seq>
</map>
```

**Benefit:** User can switch local ↔ API without losing history

### 2. Cost Optimization

## TOKEN/COST EFFICIENCY

```

Conv 3: Reload 200k + new 100k = 300k
...
```
